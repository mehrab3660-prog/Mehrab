# سلطان نور (Sultan Noor)

فروشگاه اینترنتی B2C/B2B با معماری Next.js + NestJS + PostgreSQL + Redis + Meilisearch.

این پروژه یک **اسکلت معماری کامل به همراه یک هسته‌ی MVP کاملاً کارکردی** است: مدل داده برای همه‌ی
قابلیت‌های خواسته‌شده در `prisma/schema.prisma` تعریف شده و مسیرهای اصلی خرید (ثبت‌نام با OTP، سبد
خرید، قیمت‌گذاری پلکانی B2B، پرداخت، فاکتور PDF) به‌صورت end-to-end تست شده کار می‌کنند. بخش‌هایی که
هنوز کامل پیاده‌سازی نشده‌اند (جستجوی تصویری واقعی، جستجوی صوتی، ادغام کامل درگاه پرداخت) به‌صورت
fallback عملکردی پیاده شده‌اند و در بخش «نقشه راه» زیر مشخص شده‌اند.

## معماری

```
sultan-noor/
├── apps/
│   ├── api/     # NestJS + Prisma (PostgreSQL) — REST API
│   └── web/     # Next.js (App Router) — فروشگاه + پنل مدیریت
├── docker-compose.yml   # Postgres, Redis, Meilisearch برای توسعه
└── pnpm-workspace.yaml
```

## قابلیت‌های پیاده‌سازی‌شده

- **احراز هویت با OTP** (ثبت‌نام/ورود پیامکی)، JWT access/refresh، RBAC با ۶ نقش
  (`SUPER_ADMIN`, `ADMIN`, `STAFF`, `WAREHOUSE_MANAGER`, `B2B_CUSTOMER`, `CUSTOMER`)
- **کاتالوگ کامل**: برند، دسته‌بندی درختی، تأمین‌کننده، انبار، محصول با تنوع (variant) و موجودی
  چندانباره
- **سبد خرید و علاقه‌مندی‌ها** با قیمت‌گذاری زنده
- **قیمت‌گذاری پلکانی B2B** بر اساس گروه مشتری و تعداد سفارش + **کد تخفیف**
- **سفارش و فاکتور**: محاسبه‌ی خودکار جمع/تخفیف/ارسال، رزرو و کسر موجودی در تراکنش، تولید **فاکتور
  PDF واقعی** (pdfkit)
- **پرداخت**: اتصال به زرین‌پال با fallback به حالت sandbox وقتی کلید تنظیم نشده (برای تست کامل
  جریان خرید بدون درگاه واقعی)
- **پنل تنظیمات (`/admin/settings`, فقط مدیر ارشد)**: کلیدهای API (Merchant ID زرین‌پال، کاوه‌نگار،
  Anthropic، OpenAI) و آدرس سایت مستقیماً از داشبورد قابل تنظیم‌اند — بدون نیاز به دسترسی سرور یا
  ویرایش `.env`؛ هر مقدار در پایگاه‌داده اولویت دارد و در نبود آن، همان متغیر محیطی قبلی جایگزین
  می‌شود، پس دیپلوی‌های مبتنی بر `.env` بدون تغییر کار می‌کنند
- **نظرات کاربران + پرسش و پاسخ** با تایید ادمین و اعلان خودکار
- **اعلان لحظه‌ای** با Socket.IO
- **مشاور خرید هوشمند AI**: RAG-lite روی نتایج جستجوی واقعی کاتالوگ؛ اگر `ANTHROPIC_API_KEY` تنظیم
  شود از Claude برای پاسخ طبیعی استفاده می‌کند، در غیر این صورت پاسخ قاعده‌محور می‌دهد
- **جستجوی هوشمند متنی** با Meilisearch (اگر Meilisearch در دسترس نباشد، API به‌جای کرش، فقط جستجو
  را غیرفعال می‌کند)
- **وبلاگ آموزشی و بنرهای تبلیغاتی**
- **پنل مدیریت**: داشبورد فروش، مدیریت محصول/دسته/برند/بنر/سفارش
- **Audit Log** (تغییرات حساس ادمین) و **Activity Log** (رفتار عمومی کاربر) جدا از هم
- طراحی کاملاً **RTL فارسی** و واکنش‌گرا (Tailwind + فونت Vazirmatn)

## نقشه راه (Roadmap) — چیزهایی که fallback دارند و باید کامل شوند

| قابلیت | وضعیت فعلی | برای تکمیل چه باید کرد |
|---|---|---|
| جستجوی تصویری | محصولات پرطرفدار را برمی‌گرداند | امبدینگ تصویر (مثلاً CLIP) روی `Product.imageEmbedding` + جستجوی برداری |
| جستجوی صوتی | با `OPENAI_API_KEY` کار می‌کند، وگرنه پیام خطا | تنظیم کلید Whisper یا جایگزین |
| پرداخت زرین‌پال | با Merchant ID واقعی (از `/admin/settings` یا `ZARINPAL_MERCHANT_ID`) کار می‌کند، وگرنه sandbox خودکار | اکانت واقعی زرین‌پال — از داشبورد قابل تنظیم است |
| پیامک OTP | بدون کلید کاوه‌نگار (از `/admin/settings` یا `SMS_API_KEY`) کد در لاگ سرور چاپ می‌شود | اتصال به کاوه‌نگار — از داشبورد قابل تنظیم است |
| فاکتور PDF فارسی | متن فارسی درست تولید می‌شود اما شکل‌دهی حروف عربی/فارسی pdfkit پیش‌فرض ندارد | فونت Vazirmatn + کتابخانه‌ی bidi/shaping |
| پنل مدیریت | CRUD اصلی (محصول/دسته/برند/بنر/سفارش) پیاده شده | فرم‌های کامل‌تر، آپلود تصویر، مدیریت تنوع محصول، مدیریت انبار/تأمین‌کننده در UI |

## راه‌اندازی توسعه

```bash
# 1) سرویس‌های زیرساخت
docker compose up -d          # postgres, redis, meilisearch

# 2) بک‌اند
cd apps/api
cp .env.example .env          # مقادیر را در صورت نیاز ویرایش کنید
pnpm install
pnpm prisma:migrate           # اجرای مایگریشن
pnpm seed                     # داده‌ی نمونه (سوپرادمین با شماره 09120000000)
pnpm start:dev                # http://localhost:4000/api

# 3) فرانت‌اند
cd apps/web
cp .env.example .env.local
pnpm install
pnpm dev                      # http://localhost:3000
```

> در محیط توسعه، کد OTP به‌جای پیامک واقعی در لاگ سرور NestJS چاپ می‌شود.

## دیپلوی روی سرور واقعی (Production)

بسته‌ی کامل Docker برای دیپلوی روی یک VPS در `docker-compose.prod.yml`، `apps/api/Dockerfile`،
`apps/web/Dockerfile` و `deploy/` آماده است:

```bash
git clone <repo-url> sultan-noor && cd sultan-noor
cp .env.production.example .env && nano .env      # دامنه، رمز دیتابیس، JWT secrets را پر کنید
sudo LETSENCRYPT_EMAIL=you@example.com ./deploy/deploy.sh
```

اسکریپت Docker، Nginx و certbot را نصب می‌کند، در صورت نبود swap (برای VPSهای کم‌رم) یک فایل ۲
گیگابایتی می‌سازد، گواهی SSL واقعی از Let's Encrypt می‌گیرد، ایمیج‌ها را می‌سازد، مایگریشن‌های
دیتابیس را اجرا می‌کند و در نهایت API و وب را بالا می‌آورد. قبل از اجرا لازم است رکورد DNS دامنه به
IP سرور اشاره کند و پورت‌های ۸۰/۴۴۳ آزاد باشند (مثلاً اگر sshd روی ۴۴۳ ست شده، آن را برگردانید).

پس از بالا آمدن سایت، برای ساخت اولین حساب SUPER_ADMIN: از طریق سایت با شماره خودتان ثبت‌نام کنید،
سپس نقش آن کاربر را مستقیم در دیتابیس ارتقا دهید (بسته دمو/seed در Production اجرا نمی‌شود):

```bash
docker compose -f docker-compose.prod.yml exec postgres \
  psql -U sultan_noor -d sultan_noor -c "UPDATE \"User\" SET role='SUPER_ADMIN' WHERE phone='0912...';"
```

کلیدهای API (زرین‌پال، کاوه‌نگار، Anthropic، OpenAI) را می‌توانید بعداً مستقیم از داشبورد
(`/admin/settings`) وارد کنید — نیازی به SSH یا ویرایش `.env` روی سرور نیست.

## تست end-to-end انجام‌شده

جریان کامل زیر با درخواست‌های واقعی HTTP روی این کد تست شده است:
ثبت‌نام/ورود با OTP → افزودن به سبد خرید با قیمت‌گذاری زنده → ثبت آدرس → ثبت سفارش (با رزرو و کسر
موجودی) → پرداخت (sandbox) → تایید پرداخت → تغییر وضعیت سفارش → تولید و دانلود فاکتور PDF → مشاهده
در داشبورد فروش.

## اجرای تست‌های خودکار

```bash
# تست‌های واحد/یکپارچگی بک‌اند (Jest) — بدون نیاز به دیتابیس در حال اجرا
cd apps/api
pnpm test

# تست‌های E2E (Playwright) — نیاز به API و وب واقعی در حال اجرا دارد
cd apps/api && pnpm start:dev &     # یا: node dist/src/main.js
cd apps/web && pnpm build && pnpm start &
API_LOG_PATH=/path/to/api/stdout.log pnpm --filter @sultan-noor/web test:e2e
```

> کد OTP در محیط توسعه فقط در لاگ سرور چاپ می‌شود (هرگز در پاسخ API)، دقیقاً مثل رفتار امن production.
> به همین دلیل تست‌های E2E مبتنی بر OTP به یک فایل لاگ در حال اجرا (`API_LOG_PATH`) نیاز دارند —
> این تست‌ها امنیت را دور نمی‌زنند، فقط از همان مسیر توسعه‌ی موجود برای خواندن کد استفاده می‌کنند.
